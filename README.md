# HealBot

증상별 진료과 안내에서 지역 병원 지도 검색으로 이어지는 한국어 웹 MVP입니다.

## 실행

Node.js 22 이상이 필요합니다. 외부 패키지나 API 키 없이 실행합니다.

```sh
npm start
# 개발: npm run dev
# 검증: npm run check && npm test
```

브라우저에서 포트 3000으로 접속합니다. 다른 포트는 `PORT=3001 npm start`로 지정합니다. `.env`는 자동 로드하지 않습니다.

## 현재 구현

- 반응형 한국어 화면, 증상 예시, 로딩 및 실패 상태
- 증상 키워드에 따른 관련 질환 범주·진료과 참고 안내
- 일부 응급 표현 감지 시 일반 추천 대신 119 안내
- 지역·진료과를 조합한 네이버 지도 외부 검색 링크
- 입력 검증, 요청 크기 제한, CSP, 임의 파일 접근 차단
- Node 내장 테스트 러너의 실제 HTTP 통합 테스트 및 GitHub Actions

현재 버전은 **규칙 기반 프로토타입**입니다. AI 진단·실시간 병원 조회·거리 계산을 제공하지 않습니다. 응급 표현 감지는 누락이나 오탐이 발생하며 임상적으로 검증되지 않았습니다. 감지 결과로 응급 여부를 판단하면 안 됩니다. 증상 입력은 데이터베이스나 로그에 저장하지 않습니다. 지도 링크에는 지역과 진료과만 전달됩니다.

## 구조 / API

- `src/server.js`: HTTP 진입점, 요청 검증, 정적 파일 제공
- `src/guide.js`: 증상 안내 서비스
- `public/`: 웹 화면, 스타일, 클라이언트 동작
- `test/`: HTTP 통합 테스트
- `GET /api/health`: 상태 확인
- `POST /api/guide`: `{ "symptoms": "기침과 콧물이 나요" }`

초기 검증을 위해 Node.js와 브라우저 표준 API로 구성했습니다. React/Spring Boot/MyBatis 구조는 아직 도입하지 않았습니다. DB·회원·OCR·커뮤니티·리뷰도 미구현입니다.

## 다음 개발 단계

1. 공공 병원 데이터의 이용 조건·진료과·좌표·갱신 주기 확인 후 실제 검색/상세 API 구현.
2. AI 제공자 선정, 키의 서버 측 관리, 사용자 동의 및 의료 전문가 검토를 포함한 평가 데이터 구축.
3. Spring Boot/MyBatis 및 DB 도입 여부 확정 후 회원·세션 인증·CSRF 방어 구현.
4. 민감정보 보관·삭제 정책과 업로드 검증을 정한 뒤 OCR 추가.
5. 커뮤니티·리뷰의 권한·신고·운영 정책 구현.

공개 서비스 출시 전에는 TLS, 요청 빈도 제한, 운영 모니터링, 의료 콘텐츠 검토가 필요합니다. 이 저장소는 개발용 MVP이며 배포 완료를 의미하지 않습니다.
