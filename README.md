# HealBot

증상별 진료과 안내와 지역 병원 검색을 연결하는 한국어 웹 MVP입니다.

**[개발 현황·미완료 작업·우선순위](docs/STATUS.md)**에서 작업별 상태, 완료 조건, 차단 사항과 검증 기록을 관리합니다.

## 실행

Node.js **22.19 이상**(권장: 24 LTS)이 필요합니다.

```sh
npm ci
cp .env.example .env
npm start
# 개발 서버: npm run dev
```

기본 포트는 3000입니다. `.env`를 자동으로 읽으며 프로세스 환경변수가 우선합니다. 저장소에 키나 `.env`를 커밋하지 마세요.

## 병원 검색 모드

- **기본:** 키가 없으면 병원 조회가 준비되지 않았음을 알리고 네이버 지도 검색 링크를 제공합니다. 샘플로 자동 전환하지 않습니다.
- **샘플:** `.env`에 `HOSPITAL_DEMO=true`를 설정하면 서울/내과에 가상 병원 1건이 표시됩니다. 샘플 카드는 전화·지도 링크가 없으며 실제 의료기관이 아닙니다.
- **공공 API:** `HOSPITAL_DEMO=false`와 `HOSPITAL_API_KEY`를 설정하면 건강보험심사평가원 병원정보서비스에 서버에서 요청합니다. 공공데이터포털에서 해당 서비스 이용 승인을 받고 **일반 인증키(Decoding)** 를 사용하세요. 시·도, 진료과, 페이지별 10건 조회를 지원합니다.

연동 대상: `https://apis.data.go.kr/B551182/hospInfoServicev2/getHospBasisList`

현재 클라우드에서는 인증키가 없고 이 호스트의 네트워크 접근도 거부되어 **실제 제공기관 응답 검증은 미완료**입니다. 어댑터는 합성 XML 응답으로 검증했습니다. 실제 키로 필드·코드·검색 조건의 의미를 확인한 뒤 운영에 사용하세요. 클라우드 환경 설정에서 `apis.data.go.kr` HTTPS 접근을 허용하고 키를 안전하게 설정해야 합니다. 키를 채팅에 입력하지 마세요. 네트워크 프록시는 상속된 HTTP(S)_PROXY/NO_PROXY를 사용하고 TLS 검증을 유지합니다.

병원 등록 정보는 실제 운영 현황과 다를 수 있습니다. 방문 전 전화 확인이 필요하며 실시간 진료 여부·거리·진료시간은 제공하지 않습니다.

## 현재 기능

- 반응형 한국어 화면과 증상 예시, 로딩·실패·빈 결과 처리
- 증상 키워드에 따른 관련 질환 범주·진료과 참고 안내
- 일부 응급 표현 감지 시 일반 추천 대신 119 안내
- 시·도/진료과 검색, 주소·전화·지도 링크, 페이지 이동
- 입력 및 요청 크기 검증, 외부 응답 크기·시간 제한, CSP, 임의 파일 접근 차단
- 증상·병원 API에 주소/경로별 60초당 30건 요청 제한, 429 및 Retry-After 안내
- API/서비스 테스트, 데스크톱·모바일 브라우저 테스트, GitHub Actions

증상 안내는 **규칙 기반 프로토타입**이며 AI 분석이나 의학적 진단이 아닙니다. 응급 표현 감지는 임상적으로 검증되지 않았고 누락·오탐이 가능합니다. 감지 결과로 응급 여부를 판단하면 안 됩니다. 증상은 데이터베이스나 로그에 저장하지 않습니다. 병원 API에는 증상을 전송하지 않으며 지역·진료과만 전달합니다.

## 검증

```sh
npm run format:check
npm run check
npm test
npx playwright install chromium
npm run test:e2e
```

기존 Chromium이 있는 Linux 환경에서는 설치 대신 `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`를 사용할 수 있습니다. 브라우저 테스트는 별도 포트 3100에서 샘플 모드 서버를 띄우고 종료합니다. 실제 공공 API 연동 테스트가 아닙니다.

## 구조 / API

| 경로               | 역할                                    |
| ------------------ | --------------------------------------- |
| `src/server.js`    | HTTP 요청 처리 및 정적 파일 제공        |
| `src/guide.js`     | 증상 안내 서비스                        |
| `src/hospitals.js` | 검색 검증, 공공 API 어댑터, 응답 정규화 |
| `public/`          | 웹 화면, 스타일, 클라이언트 동작        |
| `test/*.test.js`   | 서버·서비스 테스트                      |
| `test/browser/`    | Playwright 사용자 흐름 테스트           |

- `GET /api/health`: 상태 확인
- `POST /api/guide`: `{ "symptoms": "기침과 콧물이 나요" }`
- `GET /api/hospitals?region=서울&department=내과&page=1`: 병원 검색

병원 응답은 `mode`, `source`, `total`, `page`, `pageSize`, `items`를 포함합니다. 입력 오류는 400, 외부 API 실패는 502, 인증키 미설정은 503입니다. 요청 제한은 429이며 Retry-After 헤더와 retryAfter(초)를 반환합니다. 외부 API 오류 원문이나 인증키는 클라이언트에 노출하지 않습니다.

## 다음 개발 단계

1. 공공 API 실제 응답과 진료과 필터 정확성 검증, 이용 조건·갱신 주기 확인.
2. AI 제공자 선정, 서버 측 키 관리, 사용자 동의 및 의료 전문가 검토를 포함한 평가 데이터 구축.
3. React/Spring Boot/MyBatis 및 DB 도입 여부 확정 후 회원·세션 인증·CSRF 방어 구현.
4. 민감정보 보관·삭제 정책과 업로드 검증을 정한 뒤 OCR 추가.
5. 커뮤니티·리뷰의 권한·신고·운영 정책 구현.

현재는 Node.js와 브라우저 표준 API 기반입니다. React/Spring Boot, DB, 회원, OCR, 커뮤니티, 리뷰는 아직 구현하지 않았습니다. 공개 서비스 출시 전에는 TLS, 배포 구조에 맞는 분산 요청 제한, 운영 모니터링, 의료 콘텐츠 검토가 필요합니다.
