# HealBot 개발 현황과 작업 목록

기준일: 2026-11-08 (한국 시간). 이 문서를 진행 현황의 기준으로 사용합니다. 기능을 변경할 때 완료 조건, 검증 결과, 차단 사유를 함께 갱신합니다.

- **검증 완료**: 아래에 명시한 범위의 구현과 로컬 테스트가 완료됨. 운영 배포나 임상적 유효성을 뜻하지 않습니다.
- **부분 구현**: 코드가 있지만 실서비스 연동이나 원래 요구사항의 일부가 남음.
- **차단**: 외부 설정·접근 권한 등 선행 조건이 없어서 해당 검증을 진행할 수 없음.
- **미착수**: 구현을 시작하지 않음. 계획이나 CI 파일 작성만으로 기능 완료로 표시하지 않습니다.

## 현재 차단 사항과 필요한 조치

1. **병원 API**: 이전 연결 시 apis.data.go.kr에서 프록시 CONNECT 403이 발생했고 HOSPITAL_API_KEY가 없었습니다. 환경 설정에서 해당 호스트 HTTPS 접근을 허용하고 공공데이터포털 병원정보서비스 이용 승인을 받은 일반 인증키(Decoding)를 서버의 HOSPITAL_API_KEY로 안전하게 설정해야 합니다. 키를 채팅·문서·커밋에 넣지 않습니다. 설정 후 새 연결로 재검증합니다.
2. **AI**: 제공자/모델과 인증 설정을 아직 정하지 않았습니다. 키워드 결과를 AI 결과로 표시하지 않습니다.
3. **운영 서비스**: 배포 대상, DB, R2, OCR 설정은 아직 준비하지 않았습니다. 코드 푸시는 배포 완료가 아닙니다. 클라우드 개발 환경 게시와 애플리케이션 배포도 별개입니다.

## 이번 작업 기록

- 기존 코드와 원래 요구사항을 대조해 완료/부분 구현/차단/미착수 목록 작성.
- API 요청 제한 추가: 60초당 주소·경로별 30건. 건강 상태 및 정적 페이지는 제외.
- X-Forwarded-For를 신뢰하지 않아 임의 헤더로 요청 제한을 우회할 수 없게 처리.
- 제한 시 재시도 시간 안내. 안내가 제한되어도 화면의 119 안내와 외부 지도 검색 유지.
- 주소/경로 제한 기록을 최대 10,000개로 제한하고 만료 후 회수. 활성 기록을 축출해 제한이 초기화되지 않도록 처리.

## 검증 기록

- 직전 기준: API/서비스 16개, 브라우저 8개 로컬 통과.
- 이번 기준: API/서비스 19개, 데스크톱·모바일 브라우저 10개 로컬 통과.
- 브라우저 검증은 샘플 서버 및 가짜 API 응답을 사용. 실제 제공기관 연결, 의료 정확성, GitHub 원격 CI, 운영 배포는 검증하지 않음.
- 코드 검사 및 포맷 검사는 npm run check, npm run format:check. 테스트는 npm test와 npm run test:e2e.

## 요청 제한 운영상의 범위

현재 제한 기록은 프로세스 메모리에만 있고 재시작하면 초기화됩니다. 프록시 뒤에서는 같은 소켓 주소로 요청이 모여 제한을 공유할 수 있습니다. 운영에서는 배포 구조를 확인한 후 신뢰할 프록시 범위를 명시하거나 게이트웨이·공유 저장소에서 제한해야 합니다. 현재 구현을 분산 공격 방어 또는 전체 API 사용량 예산 관리로 간주하지 않습니다. IP/증상/검색어를 파일 로그나 DB에 기록하지 않습니다.
